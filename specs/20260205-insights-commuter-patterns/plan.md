# Implementation Plan: Commuter-Focused Parking Insights

**Feature**: `insights-commuter-patterns` | **Date**: 2026-02-05 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/20260205-insights-commuter-patterns/spec.md`

## Summary

Enhance the existing insights system to provide commuter-focused analysis with two new insight types:
1. **morning_recommendation** (P1): Day-specific arrival time recommendations for the 7:30am-9:30am commute window
2. **commuter_patterns** (P2): Rush hour analysis showing morning/evening rush periods (start AND end times) to understand local work habits

Technical approach: Extend `InsightsGenerator` with day-of-week data aggregation and enhanced LLM prompts, keeping changes localized to `parkride/insights.py` while maintaining the existing API contract.

## Technical Context

**Language/Version**: Python 3.11
**Primary Dependencies**: Flask 3.0, OpenAI SDK (for Ark), Anthropic SDK, SQLite3
**Storage**: SQLite (`parking_data.db`) - existing `parking_readings` and `insights` tables
**Testing**: Manual testing via dashboard and API (no automated test framework in project)
**Target Platform**: macOS local development, Linux server (collector)
**Project Type**: single
**Performance Goals**: Insight generation <60s (LLM response time dominant)
**Constraints**: Must work with existing LLM fallback chain (Ark → Anthropic → static)
**Scale/Scope**: Single user, ~1400 readings/day, 7+ carparks
